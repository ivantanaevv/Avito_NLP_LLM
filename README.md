# Avito_NLP_LLM
Решение задачи поиска статей справки Авито: парсинг HTML, BM25, char TF-IDF, Qwen embeddings, RRF, CatBoostRanker и валидация MAP@10.

# Поиск статей справки Авито

Решение задачи ранжирования статей справки по пользовательскому запросу.

## Подход

1. HTML статей разбивается на смысловые секции.
2. Секции делятся на чанки с overlap.
3. Для поиска используются BM25, char TF-IDF и Qwen embeddings.
4. Кандидаты объединяются через RRF.
5. Финальное ранжирование выполняется CatBoostRanker.
6. Качество проверяется на calibration.f с помощью 5-fold cross-validation по query_id и метрики MAP@10.

## Данные и признаки

Использованы train.parquet, benchmark_queries.parquet и benchmark_items.parquet. Из train взяты положительные пары «запрос - выбранное объявление».

Для текстового поиска используются запрос, заголовок, параметры и описание объявления. Локация помогает учитывать географическую доступность услуги. В CatBoost дополнительно передаются поисковые оценки и ранги, рейтинг, число отзывов, цена, длины текстов и флаги доступности связи.

Фильтры, категория и флаг доставки учитываются при выделении контекстов запросов для разметки и валидации, но отдельные признаки соответствия им в модели не используются.

## Проверка качества и анализ ошибок

Для локальной валидации выбраны 2 000 текстов запросов. Все взаимодействия с этими текстами исключены из обучения CatBoost. Варианты сравниваются по Recall@50 на одной проверочной выборке.

По результатам экспериментов выявлены следующие проблемы:

- Поиск только по текстовому сходству недостаточно учитывает географию. Добавление бонуса за совпадение локации заметно улучшило качество.
- Жесткое ограничение одной локацией исключило бы 17.8% положительных пар train. Поэтому объявления из других локаций остаются доступными для поиска.
- Текстовые методы пропускают часть выбранных объявлений. Добавление E5 увеличило Recall расширенного набора кандидатов с 0.7761 до 0.8513.
- Обучаемая модель не всегда лучше поисковой формулы. Вторая модель CatBoost отдельно уступила предыдущему решению, но их объединение улучшило локальное качество и результат на Stepik.

Эти выводы получены из статистики данных и сравнения вариантов; отдельная ручная классификация ошибок не проводилась.

## Результат

Лучший локальный результат: MAP@10 около 0.596.
